# Ізольований тест Google Calendar

Функція доступна тільки прив’язаному адміністратору через «🧪 Тест Google Calendar». Чинна ICS-підписка й основні задачі не замінюються.

## Ізоляція та перевірка

- Окремі таблиці calendar_lab_links, calendar_lab_connections, calendar_lab_tasks. Немає запису в commitments/occurrences, штрафів, прогресу чи ранкових планів.
- Створюється окремий приватний календар «Крок вперед · ТЕСТ 🧪». Доступ OAuth — лише calendar.app.created, без читання особистих календарів.
- Можна додати тестову задачу або явно скопіювати свої невиконані заняття на сім днів. source_occurrence_id використовується тільки для захисту від дублювання копій; зміни назад в оригінали не переносяться.
- Події з часом у тестовому календарі імпортуються в тестовий список. Інші календарі не читаються. Події на весь день пропускаються. Час початку події стає дедлайном тестової задачі; тривалість імпортованої події зберігається.
- Планувальник bot:calendar-lab перевіряє тест щохвилини. При роботі Google API та cron зміни з’являються після найближчого проходу, без гарантії миттєвості або доставки на iPhone. У чат немає повідомлення на кожен імпорт.
- Тест обмежений часовим вікном: попередні 30 і наступні 90 днів, до 2500 отриманих подій за прохід. Події, переміщені за межі цього вікна, у цьому пілоті не узгоджуються автоматично.
- Локальні зміни бота виграють одночасні зміни назви/часу. Видалення події в Google скасовує тестовий запис. Завершення в боті додає позначку «Виконано» в Google; сама зміна назви в Google не вважається підтвердженням виконання.
- Детерміновані ID створення та розпізнавання власних подій після втрати HTTP-відповіді захищають від дублів. PATCH використовує ETag/If-Match; при конфлікті повторне читання — на наступному проході. Це пілотна політика конфліктів, а не правила для зобов’язань основного бота.

## Безпека підключення

Одноразове посилання з Telegram має випадковий 256-бітний ключ і строк десять хвилин. GET лише показує сторінку; POST із CSRF споживає посилання. Callback перевіряє браузерну сесію, state, строк дії та PKCE. Токени Google шифруються APP_KEY й не виводяться в повідомленнях або експорті користувача. Винятки API замінюються загальними повідомленнями без секретів.

OAuth створення календаря не має idempotency key. Після невизначеної мережевої помилки створення слід спочатку перевірити Google, щоб не створити зайвий порожній календар. Підключення вимагає звичайного браузера, якщо Google не дозволяє OAuth у вбудованому браузері Telegram.

## Одноразове налаштування власником

1. Окремий Google Cloud-проєкт. Увімкнути Google Calendar API; платні обчислювальні ресурси не потрібні.
2. Налаштувати OAuth consent для тестового застосунку й додати тільки власний Google-акаунт як test user. Не публікувати для всіх.
3. Створити Web application OAuth client з точним redirect URI:
   `https://stepahead.korporatsiia-mov.com/calendar-lab/callback`.
4. У приватній серверній .env встановити GOOGLE_CALENDAR_LAB_ENABLED=true, GOOGLE_CALENDAR_CLIENT_ID, GOOGLE_CALENDAR_CLIENT_SECRET. Не передавати секрет у чат і не комітити його. Після зміни конфігурації очистити її кеш.
5. Через тестову кнопку відкрити сайт і надати дозвіл Google. У режимі Testing refresh token може мати обмежений строк; після втрати дозволу потрібне повторне підключення. Поточний пілот не налаштований для публічного OAuth-запуску.

## Завершення тесту

«Завершити й видалити тест» вимагає свіжого персонального підтвердження. Фоновий процес видаляє лише збережений тестовий календар, потім локальні тестові записи й токени. Основні задачі та інші календарі не видаляються. Якщо Google більше не дає доступу, автоматичне очищення може не завершитися: можна вибрати «Вимкнути, залишивши календар Google» та прибрати його в Google вручну. Дозвіл застосунку можна відкликати у своєму Google-акаунті.

Видалення особистого акаунта бота прибирає локальні тестові записи й токени, але не запускає мережеве видалення Google-календаря. Для повного завершення тесту спочатку слід скористатися спеціальною кнопкою тесту. Копії даних у Google та резервних файлах мають відповідні строки зберігання.

Після очищення GOOGLE_CALENDAR_LAB_ENABLED=false приховує кнопку, забороняє старі посилання OAuth та вимикає синхронізатор. Саме очищення треба виконати до вимкнення прапорця. Видаляти файли чи відкочувати інші міграції для цього не потрібно.

Запити DELETE подій та календаря надсилаються без тіла; Google відхиляє JSON-масив у такому запиті. Це перевірено окремим регресійним тестом і живим скасуванням тестової події.
